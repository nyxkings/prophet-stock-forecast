================================================================================
5.1  OVERVIEW OF RESULTS
================================================================================

This chapter presents the outcomes of designing, implementing, and evaluating a
Prophet-based portfolio optimisation system. Results are reported at four levels:

  (1) Implementation verification — does the system work correctly?
  (2) Primary pipeline outputs   — forecasts, expected returns, optimal weights
  (3) Risk and diversification   — tail risk, Sharpe ratio, concentration, sectors
  (4) Walk-forward backtesting   — historical forecast accuracy and strategy performance

The central design result is a working end-to-end pipeline in which Prophet
predicted returns form the expected return vector (μ), while the covariance
matrix (Σ) is estimated exclusively from the last 252 trading days of historical
daily returns. This separation prevents forecast values from contaminating risk
estimates.

Interpretation of Table 5.6:

  • Assets with the highest Prophet-predicted returns (AMD 7.59%, TSLA 7.33%)
    received the largest allocations above the 5% floor.
  • Assets with negative predicted returns (META −1.38%, PLTR −3.36%) were held

  highest-μ assets rather than saturating a single position.

    observation (2026-07-09).

5.8  WALK-FORWARD BACKTEST EVALUATION
================================================================================

A walk-forward backtest was executed over the period 1 January 2025 to
1 June 2026. At each evaluation date the system:

  1. Trained Prophet on all historical data up to that date
  2. Generated one-step price forecasts and expected returns
  3. Estimated Σ from the prior 252 trading days
  4. Solved the mean-variance problem under project constraints
  5. Compared predictions and portfolio returns to realised outcomes

5.11  LIMITATIONS OF RESULTS
================================================================================

  1. Data dependency: Results depend on Yahoo Finance (yfinance). Intermittent
     failures or rate limiting can exclude tickers from a given run.

  2. One-step forecasts: Prophet produces one-day-ahead price forecasts only.
     Multi-horizon performance is not evaluated.

  3. Constraint binding: With 12 assets and a 5% floor, the feasible set is
     small; weights often sit at corners (45% max on one asset, or split between
     two leaders as in Table 5.6).

  4. Ex-post risk metrics: Sharpe, VaR, and drawdown in Table 5.7 are computed
     on historical returns with current weights — they describe the past, not
     guaranteed future performance.

  5. Sector concentration: Asset-level minimum weights do not prevent Technology
     sector dominance (61.65% in Table 5.9).

  6. No transaction costs: Optimisation ignores trading costs, slippage, and taxes.

  7. Backtest runtime: Full walk-forward backtesting over 17 months is
     computationally intensive (one Prophet fit per ticker per evaluation date).

5.12  CHAPTER SUMMARY (CONCLUSIONS)
================================================================================

The project successfully delivers a Prophet-based portfolio optimisation system
that:

  • Extracts and aligns multi-asset price data from Yahoo Finance
  • Forecasts next-day prices using Prophet with US trading holiday effects
  • Converts forecasts to expected returns (μ) for mean-variance optimisation
  • Estimates covariance (Σ) from 252 days of historical returns only
  • Produces constrained optimal weights under λ = 5, 5% ≤ wᵢ ≤ 100%, Σwᵢ = 1
  • Persists results to Supabase and visualises them in a Streamlit dashboard
  • Provides risk, sector, and backtesting analysis via CLI commands

Empirical results from the latest run (9 July 2026) show the optimiser favouring
AMD (26.65%) and TSLA (23.35%) based on the highest Prophet-predicted returns,
while maintaining all other assets at the 5% diversification floor. Historical
risk-adjusted performance metrics (Sharpe 1.36, annualised volatility 34.2%)
are favourable over the estimation window, but sector concentration in Technology
(61.65%) remains a structural limitation of the chosen universe.

Walk-forward backtest results over January 2025 – June 2026 should be inserted
into Table 5.11 and Table 5.14 once the backtest command completes. The partial
backtest already demonstrates correct μ → weight linkage and constraint binding
at the 45% single-asset ceiling.
