RISK METRICS FORMULA REFERENCE (matches your code and Chapter 3 text):

  VaR (95%):     5th percentile of portfolio return distribution
  CVaR (95%):    Mean of returns below the VaR threshold
  Sharpe Ratio:  (mean_return - risk_free_rate) / std_return  [annualised in code]
  Sortino Ratio: (mean_return - risk_free_rate) / downside_std
  Max Drawdown:  max(peak - trough) / peak over the return series
  Volatility:    std(returns) × sqrt(252)  [annualised]

4.1 INTRODUCTION

This chapter describes the practical implementation of the Prophet-based portfolio
optimisation system developed in Python. The implementation translates the
methodological framework presented in Chapter Three into a working software
platform comprising twelve source modules, a comprehensive test suite, a
Streamlit dashboard, and automated deployment pipelines.

The system was implemented using a modular architecture in which each component
was developed and unit-tested independently before integration through the
central orchestration function run_optimisation() in src/main.py. Version control
was managed using Git and GitHub (repository: nyxkings/prophet-stock-forecast),
with continuous integration configured via GitHub Actions.

The portfolio under study consists of twelve publicly traded equities configured
in src/settings.py: AMD, MSFT, AAPL, TSLA, AMZN, NVDA, META, GOOG, TSM, JPM,
NFLX, and PLTR. Risk parameters were set to a balanced investor profile with a
risk aversion coefficient λ = 5, minimum allocation of 5% per asset, and
maximum allocation of 100%.  


4.2 DEVELOPMENT ENVIRONMENT AND PROJECT STRUCTURE

The system was developed in Python 3 using Cursor as the integrated development
environment. Dependencies were managed with Poetry (pyproject.toml) and include
Prophet, pandas, NumPy, SciPy, yfinance, Supabase, and Streamlit.

The project directory structure is organised as follows:

  src/                  — Application source code (12 modules)
  tests/                — Unit, integration, and edge-case tests
  .github/workflows/    — CI/CD and daily optimisation scheduling
  scripts/              — Deployment scripts

4.4 DATA EXTRACTION MODULE (extractor.py)

The data extraction module retrieves historical stock prices from Yahoo Finance
using the yfinance library. The function extract_data() iterates over the
provided ticker list, downloads OHLCV data for each symbol, and returns a
dictionary of processed DataFrames.

For each ticker, the helper function _process_ticker_dataframe() performs:
  (a) extraction of the closing price column,
  (b) renaming to "Price",
  (c) calculation of daily returns using pandas pct_change(), and
  (d) normalisation of the date index.

Error handling is implemented at the per-ticker level: if a symbol is invalid or
unavailable, the error is logged and that ticker is skipped rather than causing
the entire pipeline to fail.

4.6 PROPHET FORECASTING MODULE (model.py)

The forecasting module implements the ProphetModel class, which fits an
independent Prophet model for each ticker in the portfolio. The implementation
incorporates US stock exchange holidays retrieved from the XNYS calendar via
pandas_market_calendars, preventing forecasts on non-trading days.

The predict_for_tickers() method:
  1. Retrieves the current (last known) closing price for each ticker
  2. Calls predict_next() to fit Prophet and generate a one-step-ahead forecast
  3. Computes the predicted daily return as (predicted_price - current_price) / current_price
  4. Returns two dictionaries: predictions (prices) and predicted_returns (returns)

Prophet is configured with yearly seasonality enabled, weekly seasonality
enabled, and daily seasonality disabled, as defined in PROPHET_PARAMS within
settings.py.

4.7 PORTFOLIO OPTIMISATION MODULE (optimiser.py)

The optimisation module implements Markowitz mean-variance portfolio optimisation
using the Sequential Least Squares Programming (SLSQP) solver from SciPy.

The function calculate_mean_variance() constructs:
  - μ (expected returns): from Prophet's predicted_returns when provided, otherwise
    from historical mean returns
  - Σ (covariance matrix): always computed from the last 252 trading days of
    historical returns

The objective function minimised is:

  f(w) = -(wᵀμ - λ/2 · wᵀΣw)

Subject to:
  - Equality constraint: Σwᵢ = 1 (fully invested portfolio)
  - Bound constraints: 0.05 ≤ wᵢ ≤ 1.0 per asset
  - No short selling (enforced by lower bound ≥ 0)

4.8 PIPELINE ORCHESTRATION (main.py)

The function run_optimisation() serves as the central orchestrator, executing
the complete pipeline in sequence:

  Step 1 — extract_data(): download historical prices
  Step 2 — preprocess_data(): align dates and compute returns
  Step 3 — ProphetModel().predict_for_tickers(): generate forecasts
  Step 4 — collect_recent_prices(): gather recent price history
  Step 5 — optimize_portfolio_mean_variance(): compute optimal weights,
           passing predicted_returns as the expected return vector
  Step 6 — return structured result dictionary

The CLI entry point main() calls run_optimisation() with the default ticker
list from settings.py and persists results to Supabase via
save_results_to_supabase().

4.9 DATABASE MODULE (database.py)

Results are persisted to a Supabase-managed PostgreSQL database. The function
save_results_to_supabase() creates one database row per ticker for each

  - predicted_price: Prophet's next-day price forecast
  - predicted_return: computed expected return
  - portfolio_weight: optimal allocation from the optimiser
  - actual_prices_last_month: JSON array of recent closing prices

Database credentials (SUPABASE_URL and SUPABASE_KEY) are loaded from environment
variables, ensuring credentials are not hardcoded in source files.

4.11 BACKTESTING IMPLEMENTATION (backtesting.py)

The backtesting framework implements walk-forward validation as described in
Section 3.8.2 of the methodology. The Backtester class:

  1. Defines a rolling training window (default: 252 trading days)
  2. For each test date, calls run_optimisation() with history up to that date
  3. Compares Prophet's predicted prices against actual next-day prices
  4. Computes per-date metrics: price MAPE, return MAPE, portfolio returns
  5. Aggregates results into a BacktestSummary with Sharpe ratio and volatility

The risk analytics module computes a comprehensive set of risk metrics through
the RiskMetrics dataclass, including:

  - Value at Risk (VaR) at 95% and 99% confidence levels
  - Conditional Value at Risk (CVaR / Expected Shortfall)
  - Sharpe Ratio and Sortino Ratio (annualised)
  - Maximum Drawdown and Calmar Ratio
  - Volatility, skewness, kurtosis, beta, and Jensen's alpha

These metrics complement the optimisation output by quantifying downside risk
exposure and risk-adjusted performance.

4.15 IMPLEMENTATION SUMMARY

Table 4.1 summarises the mapping between system requirements and their
implemented modules.

Table 4.1: Module Implementation Summary

| Requirement              | Module File          | Key Function / Class              |
|--------------------------|----------------------|-----------------------------------|
| Data acquisition         | extractor.py         | extract_data()                    |
| Data preprocessing       | processor.py         | preprocess_data()                 |
| Price forecasting        | model.py             | ProphetModel.predict_for_tickers()|
| Portfolio optimisation   | optimiser.py         | optimize_portfolio_mean_variance()|
| Pipeline orchestration   | main.py              | run_optimisation()                |
| Result persistence       | database.py          | save_results_to_supabase()        |
| Dashboard visualisation  | streamlit_app.py     | Streamlit UI + metric functions   |
| Risk assessment          | risk_analytics.py    | RiskMetrics                       |
| Performance validation   | backtesting.py       | Backtester.run()                  |
| Configuration            | settings.py          | PORTFOLIO_TICKERS, RISK_AVERSION  |

The modular implementation ensures that each component can be tested, modified,
and extended independently. The integration through run_optimisation() provides
a single entry point for both CLI execution and backtesting, while the Streamlit
dashboard and Supabase persistence layer deliver end-to-end usability for
investment analysis and historical performance tracking.
